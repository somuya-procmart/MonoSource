# Architecture Decision Records

## ADR-001 Independent product, no coupling to ProcMart ERP
Own repo, DB, auth, API, jobs. ProcMart is an integration partner via adapter. *Evidence:* ProcMart repos contain no reusable backend.

## ADR-002 Modular monolith (NestJS)
One deployable, hard module boundaries (own tables, services, controllers). Microservices only with a concrete scaling/ownership reason.

## ADR-003 Tenant isolation with Postgres Row-Level Security
Every tenant table carries `tenant_id`, `FORCE ROW LEVEL SECURITY`, policy `tenant_id = current_setting('app.tenant_id')::uuid`. The API connects as `monosource_app` (no BYPASSRLS, not owner) and sets the tenant per transaction. A bug in a query cannot leak across customers. Platform-level operations use an explicit `app.platform = 'on'` flag set only for platform-admin tokens.
Trade-off: no ORM, SQL written by hand.

## ADR-004 Postgres transactional outbox instead of BullMQ (for now)
ERP submissions and extraction are enqueued in the same transaction as the business write, processed with `FOR UPDATE SKIP LOCKED`, exponential retry, unique idempotency keys. Removes dual-write bugs and an infra dependency. Re-evaluate BullMQ when scheduled jobs/throughput demand it (Redis is already in compose).

## ADR-005 AI is suggestion-only
Providers behind interfaces. Every AI output is stored with prompt/model/version and confidence, status `pending`, and needs a human decision row. AI cannot publish a contract line, approve an award or release a PR.

## ADR-006 Plant identity = (ERP system, plant code)
`org_nodes.erp_system_id` is part of the unique key for plant nodes. Same code on two servers = two plants.
